# AGENTS.md

## What this is
- npm package **`@jmas/wryte`**: a tag-first (markdown) rich text editor with a Trix-compatible API, built on ProseMirror. Markdown is the source of truth (`element.value` ↔ markdown); all DOM events bubble and are namespaced `wryte-*`.
- Built with Vite library mode → `dist/` (ESM `index.js`, CJS `index.cjs`, d.ts). ProseMirror packages are **peer dependencies** (externalized, never bundled); `markdown-it` is a devDependency and IS bundled into the output.

## Commands
- `npm run dev` — Vite dev server serving the preview page (root `index.html` + `demo/`). Default `http://localhost:5173`. Not part of the package build.
- `npm test` / `npm run test:watch` — Vitest (jsdom environment), tests in `tests/**/*.test.ts`.
- `npm run typecheck` — `tsc --noEmit` over `src`, `demo`, `tests`, configs. `noUnusedParameters`/`noUnusedLocals` are on.
- `npm run build` — `tsc --noEmit && vite build` (generates `dist/`). **Always run this before publishing.**
- `npm run build:demo` — static build of the preview page (root `index.html` + `demo/`) into `dist-demo/`, deployed to GitHub Pages by `.github/workflows/pages.yml` on push to `main`. The `vite.demo.config.ts` config sets `base: './'` so the site works under the `/wryte/` project-page subpath.
- `npm run changeset` — add a changeset for the next release.

## Architecture
- `src/index.ts` — the only public entry; re-exports the API and a `Wryte` namespace object. Keep the public surface here.
- `src/editor.ts` — `Editor` class wrapping a ProseMirror `EditorView`. Trix v2 method surface (`loadMarkdown`/`toMarkdown`/`loadHTML`/`toHTML`, `activateAttribute`/`attributeIsActive`/`canActivateAttribute`/`deactivateAttribute`, `insertString(s)`/`insertAttachment(s)`/`insertFile(s)`, `getSelectedRange`/`setSelectedRange`, `undo`/`redo`/`canUndo`/`canRedo`/`recordUndoEntry`, nesting methods, `getSnapshot`/`loadSnapshot`/`toJSON`/`loadJSON`, `clear`/`focus`/`blur`/`disable`/`enable`, `insertEmbed(url)`, `setImageAlt(alt)` — sets the `alt` attr on the NodeSelected block image, trimming and clearing to `null` on empty, no-op without an image selection). The heading button **cycles** the current block (paragraph → H2 → H3 → paragraph) via `toggleAttribute`/`activateAttribute` for `heading*` names; the emphasis button **cycles** inline styles the same way (none → bold → italic → strike → none) via `toggleAttribute('bold')`, and the code/spoiler button cycles (none → spoiler → code → none) via `toggleAttribute('code')`. `deactivateAttribute` still drops any heading to a paragraph. `loadDocument` recreates the editor state so history resets on load. `config.toolbar` is `false` by default; `config.contextMenu` is `true`. Images are **block** nodes (`imageType`): `insertAttachments` picks `imageType` when the attachment is previewable, `attachmentType` (inline) otherwise; HTML parsing lifts block images out of paragraphs/links via DOMParser plus `dropEmptyParagraphsBeforeImages` (removes the empty paragraph DOMParser leaves before a lifted image). Adds the `prosemirror-gapcursor` plugin so the caret can cross block images with arrow keys. **Drag & drop**: a `drop` handler in `handleDOMEvents` (runs before PM's built-in drop, so it works in jsdom where `posAtCoords` throws) catches drops carrying files — it dispatches cancelable `wryte-before-drop`, then `dropFiles` sets the selection to the drop point (via `posAtCoords`, falling back to the current selection when layout is unavailable) and calls `insertFiles`, so dropped images go through the familiar `wryte-file-accept` → `wryte-upload-request` pipeline, then fires `wryte-drop`. Drops without files return `false` to keep PM's own handling (text, in-document moves). Pasting an image copied from the OS file manager (Ctrl+V) is handled the same way in `handlePaste` — files in `clipboardData` are inserted via `insertFiles` (gated on cancelable `wryte-before-paste`, then `wryte-paste` fires), so pasted images hit the familiar upload pipeline too. `insertAttachments` inserts the first node via `replaceSelectionWith` and appends the rest at the mapped selection start — a `replaceSelectionWith` per node would overwrite each previous block since a block insertion leaves a NodeSelection. `refreshAttachments` is guarded against re-entrancy (a synchronous `respond()` dispatches a `setNodeMarkup` transaction mid-scan; without the guard the outer pass re-syncs a just-responded attachment from a stale pre-response node and re-requests its upload). **Embeds**: typing a URL on an empty line then a space (the `embedInputRule`, works only in a paragraph outside blockquotes/lists) or pasting a lone URL into an empty line (via `handlePaste`) replaces the line with a block `embed` card plus a fresh paragraph (`insertEmbed`/`insertEmbedUrl`; inside a blockquote/list the typed URL degrades to a `link` mark, and a pasted URL over a selection stays plain text). `scheduleEmbedScan` coalesces `EmbedManager.refresh()` onto the next tick — do NOT scan synchronously in `afterStateChange`, or listeners attached in the same task (after element upgrade, during the host script's initial selection ops) miss the `wryte-embed-request`. `scheduleImageScan` defers `ImageManager.refresh()` (`wryte-image-request`) the same way. Injects style sets once from the constructor (see `injectEditorStyles`): the `.wryte-spoiler` hide-on-hover style, the image look (a `.wryte-image` wrapper rendered by the `ImageNodeView` node view in `src/image-node-view.ts` — `img[data-wryte-attachment]` inside it is `16/9 aspect-ratio`, gray background, `object-fit:cover` centered, `max-width:20rem`; while an upload is pending the wrapper shows a `div.wryte-progress` SVG **progress circle** overlay — no percentage label, `stroke-dashoffset` driven by `editor.updateAttachmentProgress` on `wryte-upload-request`'s `progress()`, and by `ImageManager`'s `progress()` on `wryte-image-request` via `setProcessing`/`setProgress`), the embed card look (`div.wryte-embed`: `max-width:20rem`, flex row centered vertically, border, radius, padding; `.wryte-embed-image` 1:1 `object-fit:cover` rounded on the **left**; `.wryte-embed-body` holds `.wryte-embed-title` bold + `.wryte-embed-host` small gray — host sits **below** the title and centers vertically when there's no image/title), and hacks for ProseMirror's cursor elements — `img.ProseMirror-separator` is collapsed to 0×0, and the trailing-break line after an inline-attachment-only paragraph (`p:has(br.ProseMirror-trailingBreak:last-child):has(> a:first-child > [data-wryte-attachment]:first-child, > [data-wryte-attachment]:first-child)`) gets `line-height:0` so the empty line PM appends after a trailing inline attachment doesn't add a big gap (it self-recovers once the user types after it, since PM then drops the trailing `<br>`). Block images never hit these hacks — no trailing break, separator, link, or paragraph wrapper.
- `src/schema.ts` — PM schema: paragraph, heading (levels 2 and 3 only: the `level` attr defaults to 2, `toDOM` renders `h{level}`, and `parseDOM`/the markdown parser clamp h1–h2 to level 2 and h3–h6 to level 3), blockquote, bullet/ordered lists, code_block (`language`), hr, hard_break, **block `image` atom node** (`parseDOM: img`; toDOM renders `<img data-wryte-attachment>`), inline `attachment` atom node (`parseDOM: span[data-wryte-attachment]`; non-previewable file links); both share attrs `id, url, href, alt, filename, filesize, contentType, width, height, presentation`; **block `embed` atom node** (`parseDOM: div.wryte-embed`; toDOM renders `<div class="wryte-embed" data-wryte-url>` with optional `.wryte-embed-image` + a `.wryte-embed-body` holding optional `.wryte-embed-title` and always `.wryte-embed-host`; attrs `url, host, title, image`); marks `bold, italic, strike, spoiler, code, link` (`spoiler` renders as `<span class="wryte-spoiler">`). Note: the Trix attribute name `href` maps to the `link` mark (`markTypeForAttribute` in editor.ts).
- `code` attribute is selection-aware (`selectionCoversWholeBlocks` in editor.ts): whole-block selection → block `code_block` (merged into ONE block via `replaceSelectionWith`; deactivate splits back into paragraphs at `\n`); partial text selection or caret → inline `code` mark. The `codeBlockFromSelection`/`codeBlockToParagraphs` helpers use `descendants`-reported positions + `replaceWith`/`replaceSelectionWith` — PM `nodeAt(pos)` returns the deepest node (not the block), so manual block-range math is error-prone.
- `src/markdown.ts` — `prosemirror-markdown` `MarkdownParser`/`MarkdownSerializer` bound to our schema. Tokenizer is `MarkdownIt("commonmark", { html: false }).enable("strikethrough")`. The token stream is rewritten before parsing: `normalizeBlockquoteTokens` flattens non-paragraph blockquote content to paragraphs, `liftImagesFromParagraphs` splits paragraphs around `image` tokens so each image becomes a standalone **block** `image` node (paragraphs without images pass through untouched so markdown-it's `hidden` tight-list flag survives; an image inside a blockquote degrades to a paragraph of its alt text), and `liftEmbedsFromParagraphs` turns a paragraph whose inline content is exactly one bare URL into an **`embed`** token (embeds serialize back to the bare URL). Scope is deliberately Trix-limited (see README).
- `src/embed.ts` — embed-card lifecycle: `URL_RE` (a lone URL on a line; scheme optional, TLD must be 2+ letters so `1.5`/`v1.2` never match), `normalizeUrl`/`extractHost` (host = `new URL(...).host`), and `EmbedManager` — mirrors the upload flow: whenever an `embed` node appears, the editor dispatches `wryte-embed-request` with `{ editor, url, respond }`; a listener calls `respond({ title, image, host })` to fill the card (`succeedEmbed` in editor.ts; missing fields keep current attrs). Each URL is requested once until it leaves the document. The editor never fills cards itself.
- `src/image.ts` — external-image-source lifecycle (`ImageManager`), mirroring the embed flow: whenever an `image` node **without an attachment id** (pasted/loaded image, not an uploaded one) appears, the editor dispatches `wryte-image-request` with `{ editor, url, attrs, respond, progress }`. The original image stays visible; the host re-processes the source (e.g. downloads it to its own CDN), calls `progress(fraction)` to drive the same circular `.wryte-progress` overlay as uploads (shown on first `progress`, no percent), and `respond({ url, ... })` swaps the src (`succeedImage` in editor.ts; missing fields keep current attrs). `respond({ error })` resets the overlay + fires `wryte-image-error`. Each URL is requested once until it leaves the doc; resolved URLs are marked requested too, so a swap never loops. Images with an id (upload flow) are skipped. The `ImageNodeView` registry is re-keyed via `onUrlChange` when the src swaps, so `progress` hits the right DOM.
- `src/upload.ts` — upload lifecycle. Editor dispatches `wryte-upload-request` with `{ editor, file, attachment, respond, progress }`; listeners call `respond({url,...})` / `respond({error})`. The editor never uploads.
- `src/attachment.ts` — `Attachment` model; `setAttributes` triggers a PM node update via `attachmentDidChangeAttributes` (delegate).
- `src/toolbar.ts` — `ToolbarController` + default `<wryte-toolbar>` markup (buttons use `data-wryte-attribute` / `data-wryte-action` / `data-wryte-key`; link dialog). **Optional and detached**: the editor never creates/inserts a toolbar — `setupToolbar` only wires an explicitly supplied element (`config.toolbar` defaults to `false`).
- `src/contextmenu.ts` — `ContextMenuController`: the formatting **bubble menu** (flat, Medium-style toolbar with SVG icon buttons, no shadow). It follows the editor: appears above a text selection (via `wryte-selection-change`/`wryte-focus`, gated on the editor being focused and editable); a caret in an empty line shows an inline **`(+)` button** on the right of the line whose popup contains **block-insertion actions only** (attach, code via `editor.setBlockCode()`, quote, heading, bullet/number); right-click / long-press opens a context menu at the pointer (block popup in an empty line, formatting bubble otherwise). A **NodeSelection over a block image** opens the image-tools bubble (Trix-style): **Edit alt text** (`showAltForm`, mirroring the link form — input + Apply/Remove; Apply/Enter call `editor.setImageAlt`, the form's Remove clears the alt) and **Remove** (deletes the image). Right-clicking directly on an image NodeSelects it first (`imagePosAtPointer` via `posAtCoords`) so the image bubble opens even for an unselected image; any other block-node selection still falls back to the block popup. The alt form sets `suppressNextFocusOpen` before refocusing on Escape, so Escape closes the bubble without the refocus (which normally reopens the bubble over the still-selected image) fighting it. The formatting buttons **all stay open** after a click (`refreshActiveStates`), so the selection is kept and the user can keep formatting or press a cycling button again — the selection is only reset by the user (clicking away, Escape, blur); the bubble closes itself only if a block-code conversion collapses the selection to a caret. `config.contextMenu` defaults to `true`. Menus are floating `document.body`-appended elements with injected styles; `editor.editorView` exposes `coordsAtPos`/`posAtCoords` for placement (guarded for jsdom, which has no layout). **Gotcha:** the (+) button AND every menu button must prevent focus-steal (`mousedown` preventDefault on `button` targets) or the editor blurs, the menu closes, and the opening click never fires.
- `src/selection-highlight.ts` — a Plugin that toggles a `wryte-selected` class on block `image`, `horizontal_rule` and `embed` DOM nodes whenever the selection covers them (a NodeSelection over the node itself **or** a range that spans it — PM only natively marks NodeSelections via `.ProseMirror-selectednode`). Highlighting comes from injected CSS in `injectEditorStyles` (blue outline). Inline `attachment` nodes are deliberately not highlighted. Note: in prosemirror-model 1.25.x leaf nodes report `nodeSize` **1** (not 2), so block images/hrs/embeds span a single position — `descendants`-reported positions and selection `from`/`to` still agree (verified empirically: first block sits at position 0, subsequent blocks at their accumulated offsets).
- `src/events.ts` — `EventName` constants + `dispatchWryteEvent` (bubbling, cancelable). Event names are `wryte-*` (`wryte-before-drop`/`wryte-drop` are the file-drag lifecycle events; `wryte-embed-request`/`wryte-embed-success` are the embed-card fill events).
- `src/elements.ts` — the first-class `<wryte-editor>` custom element (auto-registered on import, Trix-style). Injects one base style, `wryte-editor{display:block}` (`injectBaseStyles`), because custom elements are inline by default. Form-associated via `ElementInternals` when usable, else hidden-`<input>` + `closest('form')` fallback (jsdom's `ElementInternals` is incomplete — no `setValidity`/`checkValidity`/`form` — so feature-detect before using). Attributes: `value`, `name`, `placeholder`, `input` (id of a hidden `<input>` holding initial markdown and receiving updates, like Trix's hidden input), `toolbar`, `autofocus`, `disabled`, `required`. Syncs the form value on `wryte-change`. `registerElement(name)` is the explicit/renamed registration entry. The Editor skips its own element `value` binding when the element already has a `value` accessor (`elementHasValueAccessor` in editor.ts). The Editor mirrors `placeholder` to a `data-wryte-placeholder` attribute and mirrors document emptiness to a `data-wryte-empty` attribute (`updateEmptyState` in editor.ts) — CSS must key the placeholder off `[data-wryte-empty]`, never `:empty`, because ProseMirror keeps a `<p><br class="ProseMirror-trailingBreak"></p>` in the DOM even for an empty document.
- `src/positions.ts` — maps Trix-style text offsets ↔ PM positions (atoms count as one char; block boundaries as `\n`).

## Conventions & gotchas
- New ProseMirror packages must be added to **both** `peerDependencies` and `devDependencies`.
- TypeScript is pinned to `^5.9`. Do NOT upgrade to TypeScript 7 (native): `vite-plugin-dts` needs the JS Compiler API. `markdown-it` must stay `^14` (prosemirror-markdown depends on it).
- Tests use jsdom; a detached editor element's events do NOT reach `document` (DOM semantics), so bubble tests append the element to `document.body`.
- Undo/redo uses `prosemirror-history`; consecutive synchronous inserts are grouped into one undo entry (`recordUndoEntry` calls `closeHistory`).
- Keyboard behavior in `src/editor.ts`: `Enter` is a chain of `enterInCodeBlock → splitListItem → createParagraphNear → liftEmptyBlock → splitBlock`. In a list, Enter makes a new bullet and lifts out of an empty list item (back to a paragraph). In a code block, Enter on a non-empty line adds a new line (normal editing), and on an empty line exits the block into a paragraph (dropping the line; a middle empty line splits the block into two code blocks around the paragraph; an empty block collapses to a paragraph). `Mod-Enter` (`newlineInCode`) also adds a new line inside a code block. Do not regress to plain `baseKeymap` Enter for lists, or Enter splits inside the list item instead of creating a new bullet.
- `loadDocument` replaces the whole state (fresh history) — do not switch it back to a single transaction without handling history.
- Releases use Changesets + GitHub Actions (`.github/workflows/ci.yml`, `release.yml`). Needs `NPM_TOKEN` + a git repo.
